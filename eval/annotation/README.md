# 检索标注说明

文件：`retrieval_labels.csv`。共 30 条查询、337 行，每行是一条查询和一款候选鞋。这些候选是四个检索系统各自前 5 名的并集（详见 [../build_retrieval_pool.py](../build_retrieval_pool.py)）。行的顺序和系统排名无关，所以看不出某款鞋是哪个系统找到的。

## 每列是什么

| 列 | 内容 |
|---|---|
| `query_id`、`query_en`、`query_zh` | 购物需求，中英文意思相同 |
| `asin`、`product` | 候选商品 |
| `category` | 亚马逊类目，比如 `Women > Athletic > Running > Road Running` |
| `review_1` 到 `review_3` | 这款鞋的评论里跟这条需求最接近的 3 条，前面标了星级 |
| `label` | **你来填**：`1` 或 `0` |

## 怎么判断

只看这一行能看到的信息（商品名、类目、3 条评论），不用去亚马逊查。

填 **1**，要同时满足两条：

1. **鞋的种类对得上**。“跑鞋”就得是跑鞋，拖鞋、凉鞋不算。需求里没指定种类的（比如“不磨脚的鞋”），这一条自动满足。
2. **有证据说明它满足这个具体需求**：评论里有人这么说，或者商品名、类目本身就说明了，比如名字里有 Waterproof、Wide。

其他情况填 **0**，包括：

- 种类不对；
- 评论说的恰好相反（查“适合宽脚”，评论说“偏窄”）；
- 种类对，但看不到任何证据（查“防水的徒步靴”，这款是徒步靴，但商品名和评论都没提防水）。

拿不准的时候：评论里有正反两种说法，以多数评论为准；完全看不出来就填 0。

## 填完以后

1. 每一行都要填 `1` 或 `0`。脚本遇到空格或其他值会直接报错，并告诉你是哪一行。
2. 保存成 CSV，列名和列的顺序都不要改。Excel 里选“CSV UTF-8”；Numbers 里用“导出 → CSV”，编码选 Unicode (UTF-8)。
3. 运行：

   ```bash
   python eval/retrieval_metrics.py
   ```

   它会打印每个系统的 Recall@5 和 MRR，并把结果写进 `eval/results/retrieval_metrics.json`。

**不要再运行 `build_retrieval_pool.py`**，它会重新生成这个文件，把你填的标签覆盖掉。
