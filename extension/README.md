# ShopSense 浏览器插件（最小骨架）

在亚马逊商品页上，用语音解读外观、聚合评论、并提示官方描述与评论的矛盾。
**无需后端即可运行**：后端没启动时，插件用页面上抓到的数据本地拼一段语音解读；后端配置好后自动接管。

## 文件结构

```
extension/
├── manifest.json   # 插件说明书：在哪些站点生效、要什么权限、快捷键
├── content.js      # 注入商品页：抓取 DOM + 浮动按钮 + 语音播报
├── background.js   # 后台：转发快捷键 + 调后端 / 本地兜底解读
├── styles.css      # 浮动按钮 + 读屏专用区的样式
├── popup.html/js   # 设置面板：后端地址、身高体重
└── README.md
```

## 如何加载（Chrome / Edge）

1. 打开 `chrome://extensions`
2. 右上角打开 **开发者模式 / Developer mode**
3. 点 **加载已解压的扩展程序 / Load unpacked**
4. 选择这个 `extension/` 文件夹
5. 打开任意一个亚马逊**商品详情页**（网址里带 `/dp/` 的页面）
6. 右下角会出现 **🔊 ShopSense** 按钮 —— 点它，或按 **Alt+V**，即可听到语音解读

> 注意：必须是商品**详情页**（有 `#productTitle` 的页面），搜索结果页不会激活。

## 接入后端（可选，但强烈建议）

接口 `POST /api/extension_query` 已经在后端实现好了（见 `agent/page.py`）。

1. 启动后端：`uvicorn backend.main:app --port 8000`
2. 点插件图标，在设置里填入后端地址（如 `http://localhost:8000`），保存
3. 之后插件会优先用后端解读，失败时自动回退到本地兜底

**后端比本地兜底强在哪：** 它拿卖家写的标题和描述，去和这一页上买家写的评论逐条比对，
命中矛盾时会把双方原话都念出来（「官方写的是 X，但有买家说 Y」），而不是本地那套
关键词猜测。它不查 Qdrant——这件商品本来就不在我们的库里，所有结论都只来自这一页
本身。没有配 API Key 时也不会报错，会退化成对页面内容的直读。

请求体（插件已经按这个格式发了）：
```json
{ "asin": "...", "title": "...", "brand": "...", "price": "...",
  "description": "...", "bullets": ["..."], "reviews": ["...", "..."],
  "image_url": "...", "question": "..." }
```
返回：
```json
{ "answer": "一段 TTS 友好的解读",
  "conflict_detection": { "has_conflict": true, "details": "...", "conflicts": [...] },
  "source": "page_llm", "reviews_read": 8 }
```

## 当前能力 vs 待办

**已经能跑：**
- 抓取亚马逊商品页的标题、要点、价格、评论、主图地址
- 浮动按钮 + Alt+V 快捷键 + 读屏 ARIA live 区
- 语音播报（中文/英文自动选嗓音，可停止）
- 本地兜底解读 + 演示版冲突检测（关键词匹配）

**下一步（按优先级）：**
1. 接后端，把"本地关键词冲突检测"换成语义判断
2. 接 VLM，对 `imageUrl` 生成"视障友好"的高质量外观描述（扣子/图案位置/版型/色彩深浅）
3. 让结论带不确定性（来源、样本量、强弱）
4. 适配第二个站点（如 Zalando），把抓取规则做成可配置的适配层
5. 找真实视障用户做可用性测试，重点验证读屏不被打断

## 已知限制

- 抓取规则是按亚马逊当前 DOM 写的，站点改版可能失效（需维护选择器）
- 冲突检测目前是关键词匹配，仅作演示，易漏报/误报
- 未做图片视觉描述（需接 VLM）
- 未加图标文件，浏览器会显示默认拼图图标（不影响功能）
